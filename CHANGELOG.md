## 2026-08-10 — смысловая перегруппировка слов/фраз в 5 колодах (g_nouns/g_adjectives/g_verbs/conj/g_phrases)

Внутри каждой колоды слова лежали по алфавиту иврита — нарезка на группы по 8 в `DecksScreen` получалась смысловой мешаниной (в одной группе изучения могли оказаться случайные, никак не связанные слова). Задача — разложить по смысловым подгруппам, а уже потом резать на группы фиксированного размера.

Затронуты 5 колод (4640 слов/фраз в `deck_words`, Supabase): `g_nouns` (1553), `g_adjectives` (1678), `g_verbs` (695), `conj` (613), `g_phrases` (101). 15 тематических колод (`family`/`food`/`body`/…) не тронуты — они уже сгруппированы по темам на уровне самой колоды.

**Метод** — `tools/vocab_tmp/semantic_regroup/`: классификатор по ключевым словам (совпадение с русским переводом, левая граница слова всегда, точная граница — по метке `$` — для коротких основ, где риск ложного совпадения внутри другого слова, напр. `боль$` vs «большая»). Для каждой колоды — своя таксономия смысловых подгрупп (люди/тело/еда/природа/дом/эмоции и т.д. для `g_nouns`; движение/речь/бытовые действия и т.д. для `g_verbs`; вопросительные/предлоги/местоимения и т.д. для `conj`; приветствия/знакомство/покупки и т.д. для `g_phrases`). Внутри подгруппы — по алфавиту (как было раньше в целом по колоде). Слова, не попавшие ни в одну подгруппу, остаются в подгруппе «Прочее» в конце (тоже по алфавиту) — это открытый словарь без тезауруса, 100% покрытие ключевыми словами недостижимо.

Итоговое покрытие тематическими подгруппами: `g_phrases` 91% (91/101 — маленькая однородная колода, разметилась почти полностью), `g_verbs` 43%, `conj` 46%, `g_nouns` 33%, `g_adjectives` 34%. Остаток — блок «Прочее».

Затем нарезка на группы: **8** слов на группу — как было, кроме `g_phrases` — там **4** фразы на группу (было тоже 8). `decks.js`: `chunkCount` для `g_phrases` 13 → 26; для остальных 4 колод число групп не изменилось (195/210/87/77 — размер группы не менялся, менялся только состав).

Побочно подтверждён пункт бэклога: `g_adjectives`/`conj` реально замусорены не-леммами — в «прилагательных» половина найденных на глаз при разметке записей на деле профессии/родственные термины в парах м./ж. рода (студент/студентка, дизайнер/дизайнерша...), в «служебных» — составные термины и топонимы (автобусная остановка, Германия, министерство внутренних дел...), а не только предлоги/союзы. Курация/лемматизация (Tier 2, см. `BACKLOG.md`) этим не закрыта — переупорядочивание существующих записей курацию не заменяет.

Безопасность данных: прогресс пользователей (`user_word_progress`) ключуется по `word_id`, не по `chunk` — переупорядочивание никому ничего не сбросило. Бэкап исходного `chunk`/`ord` — `tools/vocab_tmp/semantic_regroup/backup_original.json` (на случай отката).

## 2026-08-10 — фикс охвата маркетинговых рассылок: user_stats пишется при /start и при каждом входе, не только при сохранении прогресса

Рассылка в `api/admin.js` (вкладка «Маркетинг», сегменты) берёт получателей только из `user_stats`. Раньше строка там создавалась только в `api/sync.js` (`action:"save"`) — то есть пользователь появлялся в базе (и становился доступен для рассылки) лишь после первого реального сохранения прогресса. Часть пользователей — открыли бота/приложение и сразу закрыли, посмотрели одну карточку — физически не попадали ни в одну таблицу и были невидимы для рассылок.

**`api/bot.js` (`cmdStart`)** — при каждом `/start` строка в `user_stats` теперь создаётся/обновляется сразу (`username`/`first_name`/`language_code`/`last_seen_at`); `onConflict: "telegram_id"` гарантирует отсутствие дублей и не трогает `stats` уже существующих пользователей.

**`api/sync.js` (`action:"load"`)** — то же самое при каждом открытии приложения, не только при `/start` в боте — основной сценарий повторных заходов идёт через кнопку в уже открытом чате, без набора `/start` заново. `updated_at` при этом не трогается (остаётся моментом последнего реального сохранения прогресса) — обновляется только `last_seen_at`.

Не чинит полностью: работает только вперёд, с момента деплоя. Пользователи, открывавшие бота/приложение раньше и ни разу не попавшие ни в `user_stats`, ни в `events`/`daily_sessions`, восстановлению не подлежат — Telegram Bot API не хранит и не отдаёт список «кто открывал бота», доступны только `chat_id`, которые были явно сохранены в момент визита.

⚠️ Не закоммичено на момент записи (рабочая копия: `api/bot.js`, `api/sync.js`).

## 2026-08-09 — v1.2 (часть 3): единый экран словаря — слова + модули курса + темы + буквы одним местом, фикс BUG-023

«Словарь» был размазан по трём экранам с разной механикой навигации: плоский список слов (`DictView` внутри `ReadingScreen`), тематические колоды — отдельный полноэкранный переход по кнопке «Ещё слова» (`DecksScreen`), буквы — ещё один отдельный экран (`CardsScreen`, вход только с Home/`CheatSheet`). При этом слова, изученные через колоды, физически не могли появиться в списке словаря (см. фикс данных ниже) — «карточки отдельно» было не только UX-неудобством, но и реальным разрывом данных.

**Фикс данных (BUG-023, подробности в `BUGLOG.md`)**: `DecksScreen` писал прогресс колоды напрямую в `readingProgress` — производное зеркало, которое перегенерируется из канона `facts` при каждой миграции/сохранении и НЕ персистится напрямую. Слово из колоды выглядело изученным в рамках сессии и пропадало при перезагрузке. Исправлено переносом записи через `facts.introduceWord()` — новый мутатор наравне с `answerWord`/`reviewWord`, которые заодно получили опциональный параметр `meta` (снапшот hebrew/перевод/транслит/аудио/источник слова, снимается в момент изучения и кладётся в `facts.items['w:'+id].meta`, переживает `factsToLegacyView`/`mergeFacts`). До этого список словаря строился только из `READING_ITEMS` (бандл уроков) — слова колод физически не могли туда попасть, даже если бы прогресс сохранялся правильно.

**`helpers/dictionary.js`** (новый) — единая точка сборки словаря из любого источника: `dictionaryEntries(stats)` отдаёт готовый список (meta-снапшот с фолбэком на бандл уроков для старых записей без meta — обратная совместимость без миграции данных), `groupByLessonChapter(stats)` — та же выборка, сгруппированная по модулям `COURSE_PATH` (чисто по статическому контенту: слово → его порция → модуль курса, работает для любого слова урока независимо от наличия meta), `statusOf`/`sourceBadge`/`playAudio` — общие для UI.

**`src/screens/VocabularyScreen.jsx`** (новый) — единый экран «Мой словарь» вместо `ReadingScreen(dictOnly)`:
* сводка (в словаре/знаю/слабых, числа — кликабельный фильтр по статусу) + «Повторить всё»/«Проверить всё»;
* переключатель группировки — **«Все слова»** (плоский список + поиск, как раньше), **«По урокам»** (аккордеон по модулям курса, инлайн-разворот, только уже изученное — ретроспектива «откуда что взялось», не дублирует ленту «Пути»), **«По темам»** (существующий `DecksScreen` встроен сюда же — открытие темы «замещает» экран внутри того же компонента, «← Словарь» возвращает обратно, отдельной точки входа больше нет);
* «🔤 Буквы» — персистентная карточка над переключателем (буквы — не «слово» по типу контента, не влезают ни в один из трёх режимов), открывает существующий `CardsScreen`;
* «✨ Ты уже можешь сказать» — как было.

Любая активная сессия (карточки/квиз — по всему словарю, по модулю курса, по букве, по колоде) занимает экран целиком, переключатель прячется — чтобы не путать середину повторения с переключением режима группировки.

`ReadingScreen.jsx` сокращён до одной обязанности — карточки свежей порции при прохождении «Пути» (`soloBlock`); общие компоненты сессий (`CardsMode`, `QuizMode`, `PhraseLocksSection`) экспортированы и переиспользуются `VocabularyScreen`/`DecksScreen` вместо дублирования.

**Побочный фикс при живой проверке**: React ругался `validateDOMNesting` на вложенный `<button>` (мини-кнопки 🃏/✅) внутри `<button>` заголовка карточки модуля — невалидный HTML, браузер бы «расплющивал» вложенность и ломал клики.
