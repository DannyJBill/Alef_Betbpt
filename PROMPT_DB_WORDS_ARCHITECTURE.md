# Промт для новой сессии: архитектура БД и слов

> Скопируй всё ниже и вставь первым сообщением в новую сессию Claude Code в этом репозитории (`hebrew-app`).

---

Нужно обсудить и спроектировать единую архитектуру хранения слов/словаря для масштабирования — сейчас их три независимых источника с разными схемами, разной логикой звука и без дедупликации между ними. Прежде чем что-то менять — разберись в текущем состоянии (ниже) и предложи варианты, обсудим до кода.

## Текущее состояние (3 источника слов)

**1. `src/data/words.js` (`WORD_CATEGORIES`) — 500 слов, бандл, легаси**
- Схема: `{ id, hebrew, transliteration, translation, audio }` — без `plain`, без `gender`, без `hebrewNikud`.
- Осознанно устарел: комментарий в `src/screens/HomeScreen.jsx` прямым текстом «единый поток слов (readingProgress), не легаси WORD_CATEGORIES». Используется только как пул для квиза в `GameScreen.jsx` (перевод текстом, без озвучки).
- 202 из 500 слов без `hebrewNikud` (см. `BACKLOG.md`).
- Аудио есть у всех (одна старая партия, негендерная), кроме одного случая — был битый файл-артефакт импорта из Anki (уже почищен).

**2. `src/data/reading.js` + `src/data/grammarLessons.js` — «настоящий» словарь, бандл, курируется вручную**
- Схема reading.js: `{ id, hebrew, plain, transliteration, translation, type, lesson, audio, draft? }`.
- Озвучка — через `tools/tts/manifest.json` (627 записей) + `tools/tts/generate_tts.py` (edge-tts, 2 голоса по роду: `he-IL-AvriNeural`/`he-IL-HilaNeural`). Скрипт идемпотентен **по id+роду**, но НЕ по тексту — если поправить текст записи, а не почистить `.tts_state.json`, старое (неверное) аудио тихо останется. Это уже ловили несколько раз (см. `BACKLOG.md`, раздел «🔊 Долг по озвучке»).
- 216 слов + 73 фразы (счётчик из `tests/smoke_v7.mjs`).
- Аудио-файлы лежат в `public/reading/`.

**3. `deck_words` в Supabase (проект `pikoccutljmlkfondcxc`, «AlefBetBot») — 462 слова, 15 колод, БД, динамический контент**
- Схема (после недавней миграции `add_audio_gender_to_deck_words`): `{ id, deck, chunk, hebrew, plain, translation, transliteration, ord, audio, gender }`.
- Осознанно вынесено в БД с этапа 5 (см. комментарий в `src/data/decks.js`) — чтобы редактировать без передеплоя. `api/decks.js` — плоский эндпоинт (content/load/sync).
- Озвучка сделана **отдельным одноразовым проходом** мимо `generate_tts.py`: скрипт-companion сгенерировал 462 mp3 через edge-tts (те же голоса/rate) и залил их в **тот же** `public/reading/`, гендер — эвристика по окончанию + 29 ручных поправок на известные исключения иврита (יד/רגל/עין/אוזן и т.п.). Никак не интегрировано с manifest.json/generate_tts.py — если добавится новое слово в deck_words, для его озвучки нет автоматизированного пути.
- `RLS выключен на deck_words` (и всех остальных 7 таблицах проекта) — anon-ключ может читать/писать всё. Зафиксировано в `BACKLOG.md` как критичный пункт, ничего не включено.
- Колода «Разное» (misc) — 140 слов без подтем, тоже в бэклоге на разбивку.
- `DECKS_UNLOCK_NODE = null` — все колоды открыты сразу, не встроены в общий граф прогресса, в отличие от остального курса.

## Что общее (уже единообразно, трогать не нужно)
- Все mp3 (и бандл, и колоды) физически лежат в одной папке `public/reading/`.
- Один плеер везде: `playAudio()` + `<SpeakBtn>`/`CardsMode` (см. `src/screens/ReadingScreen.jsx`, `src/screens/LessonScreen.jsx`).
- Один и тот же движок озвучки (edge-tts, 2 голоса по грамматическому роду).

## Известные боли, которые стоит решить
1. **Дублирование слов без дедупликации** — вероятно, значительная часть 500 слов `words.js` пересекается с 462 словами `deck_words` и/или 216 словами `reading.js`, но под разными id и в разных схемах. Масштаб пересечения не оценивался.
2. **Разные схемы** — четыре разных набора полей на, по сути, одну и ту же сущность «слово».
3. **Два независимых, не связанных друг с другом озвучко-пайплайна** (manifest.json+generate_tts.py для бандла vs ручной one-off для колод) — при росте словаря это будет дублироваться и расходиться дальше.
4. **Цель роста словаря** — по `BACKLOG.md`/`CURRICULUM_v2.md`, план Алеф хочет 800–1200 слов, сейчас ~600 уникальных (по факту, с учётом вероятного пересечения — возможно меньше). Непонятно, где должны появляться новые слова: в бандле, в БД, в обоих?
5. **RLS выключен** — отдельный, но смежный вопрос (тот же `deck_words`).

## Вопрос к обсуждению
Нужна ли единая модель хранения слова (одна схема полей, один источник правды, один путь озвучки) — и если да, то где ей жить: в бандле (как уроки, с ревью), в БД (как колоды, редактируется без деплоя), или гибрид (авторский мастер-список + рантайм-таблица, синхронизируемая билдом)? Как быть с уже разошедшимися 500+462+216 словами — сливать, дедуплицировать, метить дубликаты? Обсуди варианты и trade-off'ы, прежде чем предлагать миграцию.
